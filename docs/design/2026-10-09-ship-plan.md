# Pika Patrol Ship Plan

**Goal:** ship one final release (3.5.0) to Google Play and the App Store that clears every store blocker and every open bug, then close out the UBC contract.

**Source:** [`docs/FEATURES.md`](../FEATURES.md). Section numbers below (§) point there.

## Principles

- **One release, not many.** Each store submission costs days of review and back-and-forth with Megan and Jo. Batch everything into 3.5.0.
- **Blockers first.** Nothing else matters until Google Play accepts a build, so the toolchain upgrade comes first.
- **Ask for answers on day one.** Five decisions and a few pieces of content come from other people. Ask today so they arrive while the code work happens.
- **Cut scope hard.** Anything that needs a decision we don't get in time, new funding, or a privacy policy change moves to "After ship". It does not hold up the release.

## Phase 1 — Clear store blockers (§1, §11, §12) — about 3–5 days

This is the riskiest work. Do it on a fresh branch off the current one.

1. **Upgrade the toolchain.** Update Flutter stable, AGP 8.x, Gradle 8.x, Kotlin 1.9+, and Java 17. This fixes 16 KB page size support and lets the app target API 35.
2. **Set `compileSdk` and `targetSdk` to 35.** Keep `minSdk` as low as the new plugins allow, then compare the supported device count with the 3.3.8 count. That explains the 915 dropped devices.
3. **Upgrade the Firebase packages** (firebase_core, firebase_auth, cloud_firestore, firebase_storage). This brings reCAPTCHA to 18.4.0 or newer. Check with `./gradlew app:dependencies | grep recaptcha`.
4. **Turn on the Android Photo Picker** (`useAndroidPhotoPicker` or the newer image_picker default). Confirm the merged manifest has no READ_MEDIA_IMAGES or READ_MEDIA_VIDEO.
5. **Add `ios/Runner/PrivacyInfo.xcprivacy`** with FileTimestamp and UserDefaults reasons.
6. **Remove unused iOS keys:** `NSLocationAlways*` and the `remote-notification` background mode. This also stops the ITMS-90078 warning.
7. **Fix the breakages the upgrade causes.** Smoke-test on one Android 15 device or emulator and one iOS device.
8. **Build the `.aab`** with the R8 mapping and native symbols. Upload it to the Play **internal testing** track right away. This proves the blockers are gone before any other work goes in.

**Exit check:** Play Console accepts the internal-testing build with no errors.

## Phase 4 — Firebase hygiene and a hard spending cap (§13) — about 2 days

### Spending cap: RMW must never get a bill

A budget alert alone only sends email; it does not stop charges. The cap needs several layers.

1. **Free-tier check:** confirm the Storage bucket is in a free-tier region (`us-central1`, `us-east1` or `us-west1`). If it isn't, plan a move.
2. **Budget with alerts:** create a Cloud Billing budget of $1 on the Pika Patrol project. Alert at 50%, 90% and 100%, and email Megan and Chris.
3. **Kill switch:**
   - Wire the budget to a Pub/Sub topic.
   - A small Cloud Function subscribes to that topic. When the cost reaches the budget, it **detaches the billing account** from the project through the Cloud Billing API.
   - This stops all paid usage. Storage and other Blaze-only services then stop working until someone re-links billing, so the app fails safe instead of running up a bill.
   - Budget data lags by a few hours, so the cap limits spending to a few cents, not exactly $0.
4. **Per-API quota caps:** in Google Cloud Console → Quotas, set daily request limits on the Firestore, Storage and Identity Toolkit APIs. Set them just above normal use, so a runaway loop or abuse hits a wall before it costs money.
5. **Limit what can be uploaded:**
   - Storage rules accept only images and audio, under a size limit (for example 10 MB), from signed-in users.
   - Photos are compressed in the app (Phase 2).
6. **Block abuse:**
   - Restrict API keys to the app's package name and bundle ID.
   - Turn on Firebase App Check, so only the real app can call Firestore and Storage.
7. **Admin full sync:** keep it admin-only, and confirm it stays inside the free read quota.
8. **Write it down:** add a short runbook to `docs/` covering what the alerts mean, what happens when the switch trips, and how to re-link billing.

Under the personal standards, the kill-switch function is shareable (any Firebase project can use it). Build it as its own small repo, wired in as a git submodule, not inside this app.
