## Google Play Data safety form

Answers based on what the 3.5.0 code collects. The app has no ads, no analytics and no crash reporting SDK,
and it sells no data. "Shared" means sent to a third party: observation data goes to the partner
projects' Google Sheets that the observer picks; profile data goes only to the master sheet that RMW owns.

| Data type (Play category) | Collected | Shared | Required or optional | Purpose |
|---|---|---|---|---|
| Location: precise location | Yes | Yes, with chosen partner projects | Optional (coordinates can be typed) | App functionality |
| Personal info: name | Yes | No | Required | Account management, app functionality |
| Personal info: email address | Yes | No | Required | Account management |
| Personal info: address (street, city, state, ZIP) | Yes | No | ZIP required, rest optional | App functionality |
| Personal info: user IDs | Yes | No | Required | Account management |
| Personal info: other info (pronouns, organization, tagline, newsletter opt-ins) | Yes | No | Optional | App functionality, developer communications |
| Photos and videos: photos | Yes | Yes, with chosen partner projects | Optional | App functionality |
| Audio: voice or sound recordings | Yes | Yes, with chosen partner projects | Optional | App functionality |
| App activity: other user-generated content (observation notes and answers) | Yes | Yes, with chosen partner projects | Required to submit an observation | App functionality |

Security practices:

- Data is encrypted in transit: **Yes** (Firebase and Google Sheets use HTTPS).
- Users can request data deletion: **Yes.** In the app: Profile → Delete account deletes the login, profile and observations. Play also needs a **web link** for deletion requests; Megan to add the page or email address used in the privacy policy.
- Independent security review: **No.**
